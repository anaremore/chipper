# Independent audio references

Reference WAVs are intentionally not generated by Chipper and are not committed
without a provenance and redistribution review. For each accepted capture,
record the chip/model, clock, register/event trace, capture source, upstream
version or hardware setup, license/permission, sample rate, channel layout, and
expected comparison thresholds.

Render the same trace with `chipper_render`, then gate it with:

```text
python tests/compare_reference_wav.py reference.wav candidate.wav --min-correlation 0.995 --max-normalized-rmse 0.10 --alignment-window-frames 256 --max-accepted-lag-frames 64 --max-length-difference-frames 0
```

The comparator requires matching sample rates and channel counts. It preserves
each channel, finds one shared integer-frame alignment inside the bounded search
window, reports the accepted lag and full duration difference, and evaluates
correlation, gain-matched normalized error, and raw RMS ratio per channel.
Swapped stereo channels, polarity errors, and truncated or extended tails are
therefore not hidden by mono downmixing or comparison against only the shorter
file.

The defaults search up to 256 frames of capture offset and require equal total
duration. Use `--max-accepted-lag-frames` and
`--max-length-difference-frames` to state a different capture contract
explicitly; do not widen them merely to make a failing render pass. The
alignment window must be at least as large as the accepted lag.

Thresholds must be justified per capture; they are not an accuracy certificate
on their own. Hardware and trusted-emulator references should remain
distinguishable in filenames and metadata. Keep reference audio out of Git
until its license permits redistribution; CI can fetch an immutable,
checksum-verified fixture from an approved source when redistribution is not
allowed.
